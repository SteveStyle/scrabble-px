# Rules

The decisions about how the service behaves, kept apart from the design notes
that explain how they are met. Tests and commits cite the ids.

**This list is incomplete on purpose.** A rule is here because someone decided
it and it is worth remembering. Nothing being written about an area means
nobody has decided, not that anything goes.

Three questions decide whether something belongs. Was it decided, or does it
follow from the game — premium squares and word validity come from FISE and
SOWPODS, and a second copy here could only disagree with the first. Could a
reader recover the intent from the code, or only the behaviour. And would a
disagreement with the code be a bug rather than a preference.

Unlike the 4.x documents there is no freshness stamp. A reference document
that has gone stale is wrong; a rule the code disagrees with means the code is
wrong, or the rule changed and nobody said so.

## Accounts

**ACC-1** A signed-in session lasts at most 10 days, and ends after 48 hours
unused. Signing in again starts a new one.

**ACC-2** Staying logged in is a choice about what the device remembers. It
does not extend ACC-1.

**ACC-3** A player's rating history belongs to the player, not to the games
that produced it. It survives those games and goes when the account does.

## Deleting an account

This is the administrator's tool for clearing out old data, and it removes the
record outright. Closing your own account and shutting out a problematic one
are different problems: both would mark the account rather than remove it, and
neither has been analysed yet. Nothing here applies to them.

**DEL-1** An account can only be deleted through the admin CLI, run on the
machine hosting the service.

**DEL-2** An account cannot be deleted while anything still refers to it: a
game it created, a seat it holds, or an invitation it has not answered —
whatever state that game is in, and whether or not the seat has been given up.

**DEL-3** Declining answers an invitation. Only one still awaiting a reply
holds the account.

**DEL-4** DEL-2 is only reasonable because references expire on their own.
Every game goes eventually and takes its invitations with it, so waiting is
always an option and no account can be held open forever. RET-3 is what makes
that true of unanswered invitations, which live only on unstarted games.

**DEL-5** Removing a game from your own list hides it from you. The game
still exists and still refers to you, so DEL-2 still refuses — an account with
an empty games list is not necessarily deletable.

**DEL-6** A refusal names the games responsible.

**DEL-7** Deleting an account removes everything personal to it — sessions,
invitations sent and received, current rating, rating history — and nothing
belonging to anyone else.

**DEL-8** Deleting an account that never existed is reported differently from
refusing to delete one that does.

**DEL-9** The CLI takes a display name or an account id, and both reach the
same account.

## Games

**GAME-1** Aborting a game gives up every seat at once, whatever state the
game had reached.

**GAME-2** A game ends once at most one seat is still playing.

## Ratings

**RATE-1** A game an administrator force-ends changes nobody's rating.

**RATE-2** A player who resigns is ranked and rated for the game, below
everyone who finished it. Resigning is a way of ending your game, and it
counts as one.

**RATE-3** A seat that is force-resigned or times out is left out of the
result entirely, as though it had never been in the game: not ranked, not
rated, and no part of anyone else's comparison. Neither is something the
player chose.

## Retention

**RET-1** A completed game — finished or aborted — is deleted seven days
after it ended.

**RET-2** Deleting a game leaves the rating history it produced, per ACC-3.

**RET-3** A game that never started runs a thirty-day countdown from its last
activity. Seven days in, its creator is
asked what to do with it, and the question stands until they answer or the
countdown takes the game, so it may be answered on day eight or on day
twenty-nine.

- **delete** — the game goes immediately
- **keep** — counts as activity, so the thirty days start again
- **no answer** — the countdown carries on

A creator answering keep every twenty-nine days holds a game indefinitely,
which is the point: the rule clears games nobody is waiting on, not games
somebody still wants. Not built yet, and DEL-4 depends on it.

**RET-4** A game is removed no sooner than RET-1 allows, but not necessarily
promptly. Removal happens while the service is being used, so a quiet week
delays it.

## Move time limits

**TIME-1** Every game has a move time limit. It cannot be turned off.

**TIME-2** The limit defaults to 72 hours and can be set between one hour and
forty days. So a game always ends eventually, which is what makes DEL-2
tolerable — an account blocked by a game is not blocked indefinitely.

**TIME-3** A seat that exceeds the limit is retired, and the tiles it held go
back into the bag.

**TIME-4** The player on turn is emailed once when a third of their time
remains, for limits longer than a day.
